Specify isn't competing with AI coding tools — it's the delivery system that sits on top of them.

## Completiv

*"Everyone else is generative. We're completive."*

*"Cursor generates code. Completiv delivers solutions."* — *"Genesis is free. Delivery is the business."*

*"Completiv is named for the completive aspect — the grammatical form that marks work carried through to its promised end — because generation is now free, and completion is the business."*

From *complēre*, to fill full: complete and fulfil are the same word, which is why the name means delivery rather than mere stopping. It answers the category in its own technical register — "generative" is a linguistics term too, and generative grammar is the machinery of unbounded production: infinite well-formed output, none of it owed to anyone. The completive is the opposing form, the one that marks work brought to its promised state. Generative produces; completive fulfils. The timing does the arguing: AI made generating code free, so the scarce act left in software is completion — traced to source, checked against spec, approved by a human, shipped — the act the company is named for. Where finitive carried a faint "finite = limited" echo, completive carries none; its only resonance is fulfilment. Risk: the word is obscure and lands a beat slower than "definitive" — but that obscurity is exactly why the name was still ownable in 2026 when every other certainty-word was taken, and the tagline does the explaining the word doesn't.

## Finitor

The Roman term for **the horizon** — the circle that bounds the visible world, the line where open sky meets solid ground. A company that takes open-ended generation and brings it down to delivered earth, named for the line where they meet. That's the best brand story discovered in this whole exercise, and it was hiding in the cleared candidate.

## ~~Finitiv~~

From finire, to finish — the missing sibling of "definitive".

It's built in direct opposition to the category's own word: "Everyone else is generative. We're finitive." Generative produces; finitive finishes. One word, and the entire industry's self-description becomes your foil. Risk: a faint "finite = limited" echo — mitigated by the "definitive" resonance.

## The narrative arc

### 1. The setup

AI changed the cost structure of code, not of delivery. AI made writing code nearly free. But businesses don't have a "writing code" problem — they have a delivery problem: knowing what to build, proving it was built right, and being able to audit why. Vibe coding gets you a demo; it doesn't get you a system you can stand behind.

### 2. The problem

The problem — AI-generated code is unaccountable. This is your strongest wedge, because it's what Specify is genuinely built for:

> Where did this requirement come from? Nobody knows — it was a prompt three weeks ago.
> Did the AI build what we agreed? There's no spec to check against.
> What happens when sources disagree? (the legacy code says X, the design doc says Y) — the AI silently picks one.

### 3. The answer

Specify makes AI delivery accountable. Map your actual mechanics to business language:


| What Specify does                                                | How to say it on a slide                                                               |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Evidence extraction + provenance (Sources: on every requirement) | "Every requirement traces back to a real source — legacy code, docs, or stated intent" |
| Authority resolution + [conflict]/[divergence] tags              | "When sources disagree, Specify surfaces it instead of letting the AI guess"           |
| Gate 1 (operator stamps approved)                                | "A human approves the plan before any code is written"                                 |
| refine → build → merge, deterministic CLI validation             | "A repeatable production line, not a chat session"                                     |
| Baseline specs version-controlled with code                      | "The system's behaviour is documented, diffable, and auditable — forever"              |


### 4. The proof point

Legacy migration. Your TypeScript → Rust WASM input is the killer demo, because it's a problem businesses already know they have and codegen alone demonstrably fails at: "Point Specify at your legacy service. It reconstructs the spec from the code, shows you where the code contradicts your documentation, and rebuilds it — with every requirement traceable."
