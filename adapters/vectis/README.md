# Vectis Adapter (legacy assets)

The Vectis adapter manifest, briefs, and skill bodies have moved to [`targets/vectis/`](../../targets/vectis/) per RFC-25 W2.6. The files that remain in this directory are shared assets the WASI tool (`specify tool run vectis -- …`) and downstream consumers still resolve by their published `$id`:

- [`composition.schema.json`](composition.schema.json) — JSON Schema for `composition.yaml` validation. Regenerated by `targets/vectis/briefs/build.md`; validated by `specify tool run vectis -- validate composition`.
- [`tokens.schema.json`](tokens.schema.json) — JSON Schema for the operator-curated `tokens.yaml` build input.
- [`assets.schema.json`](assets.schema.json) — JSON Schema for the operator-curated `assets.yaml` build input.
- [`codex/`](codex/) — Vectis-specific review rules consumed by the Vectis reviewer passes inside [`targets/vectis/briefs/build.md`](../../targets/vectis/briefs/build.md) and [`targets/vectis/briefs/merge.md`](../../targets/vectis/briefs/merge.md).
- [`examples/`](examples/) — reference compositions kept for documentation.

These files will move under `targets/vectis/` (or be promoted to a top-level `schemas/vectis/` location) in W5.2; the present directory is the cleanest place to host them until that chunk lands without breaking the published `$id` URLs.

## Feature-centric specs

Specs are organised by **feature** (what the app does), not by software component. A single feature spec at `specs/<feature>/spec.md` contains:

- **Core requirements** (main body) — platform-neutral behavioural requirements that drive the Crux shared crate.
- **Platform sections** (optional) — platform-specific behavioural requirements in dedicated sections (`## iOS Shell Requirements`, `## Android Shell Requirements`, etc.).
- **Design system requirements** (optional) — token change requirements in a `## Design System Requirements` section.

One spec per feature merges into one baseline — no combining across component boundaries.

## Platforms

The slice's `proposal.md` declares which platforms it targets. Platforms determine which sub-agent generation passes the `build` brief drives, not how specs are structured.

| Platform | Description |
|----------|-------------|
| `core` | Rust Crux shared crate (always required) |
| `ios` | SwiftUI iOS shell |
| `android` | Kotlin/Jetpack Compose Android shell |
| `web` | Web shell (future) |
