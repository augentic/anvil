# Migrating from Specify 2.0 to 2.1

Specify 2.1 is **strictly additive** over 2.0. There is no migration script. Every existing `plan.yaml`, `evidence/*.yaml`, `discovery.md`, `.metadata.yaml`, and adapter manifest validates without change. New verbs and flags are opt-in; existing rhythms are preserved verbatim.

The normative spec lives at [`rfcs/rfc-27-synthesis.md`](../../rfcs/rfc-27-synthesis.md); the implementation plan and its outcomes are tracked in [`rfcs/rfc-27-plan.md`](../../rfcs/rfc-27-plan.md) and [`rfcs/rfc-27-acceptance-matrix.md`](../../rfcs/rfc-27-acceptance-matrix.md).

## Upgrade path

Bump the binary and the plugin marketplace; nothing else is required.

```bash
# Update the CLI binary
brew upgrade specify       # or however your platform installs it

# Reload the plugin marketplace in Cursor (Cmd-Shift-P -> "Plugins: Reload")
# or, on the CLI:
make use-team-plugins      # picks up the 2.1.0 plugin tag
```

After the upgrade the default rhythm is unchanged:

```bash
/spec:plan <name> source legacy=./vendor/monolith
specify plan transition <name> reviewed
/spec:execute
/spec:finalize <name>
```

No migration script runs; no on-disk files are rewritten.

## What's new (opt-in)

### `code-runtime` source adapter

Captured fixture trees become first-class Evidence. Bind a fixture directory the way you bind any source:

```yaml
# plan.yaml fragment
sources:
  runtime:
    adapter: code-runtime
    path: ./fixtures/replay
```

`extract` emits `kind: example` claims with `fixture-digest: sha256:…` anchors and default `authority: behaviour`. The 64 KiB inline cap lives in the brief; over-budget fixtures carry only the digest + path. Existing operators who do not bind `code-runtime` see no behavioural change.

Target adapters MAY consume the same fixtures at `build` time and record results in `.specify/slices/<slice>/.metadata.yaml`:

```yaml
fixture-replay:
  passed: 47
  failed: 0
  skipped: 0
  ran-at: 2026-05-22T13:18:42Z
  runner: omnia-target@1.4 (cargo nextest)
```

Omission is not an error. `merge` surfaces a one-line summary in its closing message when the block is present and does **not** auto-refuse on `failed > 0` in v1 — the operator decides whether to land the slice.

### Authority widening

Authority becomes a property of `(Evidence document, claim kind)`:

```yaml
# evidence/legacy-monolith.yaml fragment
authority: behaviour
authority-overrides:
  decision: documentation   # decisions extracted from comments outrank decision claims sourced elsewhere
```

Per-slice operator overrides land at Gate 1 via the plan:

```bash
specify plan amend <plan> <slice> --authority-override <kind>=<source-key>
specify plan amend <plan> <slice> --clear-authority-override <kind>
specify plan amend <plan> <slice> --clear-authority-overrides
```

`specify slice validate` rejects orphan source keys with `slice-authority-override-orphan-source-key`. Resolution order: per-slice → per-Evidence → document-level → conflict.

### Reconciliation index (`fusion.yaml`)

Each `/spec:refine` writes `.specify/slices/<slice>/fusion.yaml` listing every `REQ-*` id and every `(source, claim-id)` pair the synthesis consulted. Inspect via:

```bash
specify slice fusion show <slice> [--format text|json]
```

`specify slice validate` enforces id-set parity between `spec.md` and `fusion.yaml` and resolves every contributing-claim against `evidence/*.yaml`. Drift surfaces as `slice-fusion-drift`. The file is audit-only — `spec.md` remains the authoritative artifact for `/spec:build`.

### Candidate aliases

`## Candidate inventory` blocks carry an optional `aliases: [<kebab>, ...]` field; `slices[].sources[].candidate` resolves first against `id`, then against `aliases[]`. The CLI rewrites operator input to the canonical `id` before persisting:

```bash
specify plan add <plan> <slice> --sources <key>=<id-or-alias>
specify plan amend <plan> <slice> --add-alias <candidate-id>=<alias>
specify plan amend <plan> <slice> --remove-alias <candidate-id>=<alias>
specify discovery show --aliases
```

### Auto-review at create

`--auto-review` stamps `lifecycle: reviewed` atomically with create. Valid on any plan shape; the flag *is* the operator's Gate-1 consent.

```bash
specify plan create <name> --auto-review --intent "fix typo in user.rs"
```

The CLI emits both `plan.create` and `plan.transition.reviewed` in a single atomic journal append. Running the explicit `specify plan transition <name> reviewed` after `--auto-review` is a no-op.

### Cache fingerprints

Every `extract` cache lookup keys on the closed five-input fingerprint: source path canonicalised, adapter `name@version`, brief sha256, sorted declared-tool versions, candidate id. Misses report a closed `reason` (`no-prior-entry`, `source-path-changed`, `adapter-version-changed`, `brief-sha-changed`, `tool-version-changed`, `adapter-opt-out`). Inspect via:

```bash
specify source resolve --explain <adapter>
```

Adapters opt out of fingerprinting with `cache: opt-out` on `adapter.yaml`.

### Skill writer ownership

The CLI is now the single writer of `plan.yaml.slices[].divergence` across **every** value of the closed enum. The plan skill no longer hand-edits `plan.yaml`; it invokes `specify plan amend <plan> <slice> --divergence likely`. Operators who never authored their own plan-editing tooling see no change.

## What hasn't changed

- The default `/spec:plan` → Gate-1 stamp → `/spec:execute` → `/spec:finalize` rhythm.
- The closed authority enum (`intent | documentation | behaviour`). 2.1 lifts authority from per-document to per-(document, kind) without adding new classes; see [`docs/explanation/decision-log.md`](../explanation/decision-log.md) for the rationale.
- The on-disk schemas. Every new field is optional; every existing artifact validates without change.
- Existing CLI verbs and exit codes. New verbs and flags only.
- The synthesis-tag posture: `[conflict]` and `[divergence]` remain operator review signals, not gates. `merge` does not auto-refuse on fixture-replay failures in v1.
- `shape` capability on target adapters is unchanged.

## For adapter authors

- **Source adapters** — `code-runtime` ships as a new first-party adapter. Existing source manifests need no edits. The optional `authority-overrides` map on Evidence files and the optional `aliases[]` field on candidate blocks are both opt-in. The optional `cache: opt-out` flag on `adapter.yaml` defaults to fingerprint-on / cache-on (existing behaviour).
- **Target adapters** — The build-time fixture-replay hook is optional in v1. Targets that omit it produce no `fixture-replay:` field; omission is not an error. Targets that implement it write the block to `.metadata.yaml` and emit the `slice.fixture-replay.completed` journal event. `shape` is unchanged.

## For skill authors

- `plan.yaml.slices[].authority-override` is a new optional field; consumers ignoring it preserve existing behaviour.
- `fusion.yaml` is a new artifact at `.specify/slices/<slice>/fusion.yaml`. Consumers wanting machine-readable resolution traces use `specify slice fusion show <slice> --format json`. Consumers ignoring it preserve existing behaviour.
- The plan skill (`plugins/spec/skills/plan/SKILL.md`) no longer hand-edits `plan.yaml`. Skill bodies that previously copied that pattern should switch to invoking the CLI.
- The refine skill (`plugins/spec/skills/refine/SKILL.md`) now writes `fusion.yaml` between tasks-write and validate. See [`plugins/spec/references/synthesis/fusion.md`](../../plugins/spec/references/synthesis/fusion.md) for the reconciliation playbook.

## Roll back

There is no roll-back script because there is no migration script. If 2.1 breaks something you care about, pin the binary to the prior tag and the plugin marketplace to the prior commit; every artifact written under 2.1 (including `fusion.yaml`, `authority-override` maps, `aliases[]`, `authority-overrides`, the cache `index.jsonl`, the `fixture-replay` block) is ignored by 2.0 binaries and validates against 2.0 schemas because every field is optional. The repository state survives the downgrade unchanged.
