# RFC-62 implementation notes — baselines and phase gates

Concise measurement record for the RFC-62 migration (per Phase 0: "store the comparison in the implementation PR description or a concise RFC implementation note"). All timings are wall-clock `real` seconds on the same development machine; treat them as indicative, not benchmarked.

## Phase 0 — baselines

- Revision: `c2751278` (plus the uncommitted RFC/WIT work), toolchain `rustc 1.96.0`.
- `cargo make test` (warm tree): 271.3s — **failed** at `framework::no_framework_findings` on pre-existing stale links to the deleted `rfcs/handler-routing.md` (fixed in Phase 1 groundwork). Baseline runs shared the machine with the coverage run, so warm/cold are noisy.
- `cargo make test` (cold scratch checkout): 182.6s (same pre-existing framework failure).
- `cargo make dev -- check` (warm): 123.4s.
- `cargo llvm-cov nextest -p workflow --summary-only`: regions 34.26%, functions 36.52%, lines 33.73% (164.0s).
- `cargo make ci` and `cargo make test-replay` were exercised for correctness, not timed as baselines (the composed replay rung requires WASM guest builds and is scheduled/manual).

## Phase 1 — native confidence

- Suite: `cargo make test` green, 263 tests (baseline: 253 passing outside the framework failure). New workflow integration binaries: `full_loop`, `reconciliation`, `synthesis`, `judgment`, `adapter_seam` (ten tests) over the fixture provider (`crates/workflow/tests/common/fixture.rs`) and the native fixture core (`harness/fixtures/src/lib.rs`), plus the fixture crate's `invalid-request` boundary test.
- `cargo llvm-cov nextest -p workflow --summary-only`: regions 58.29%, functions 62.00%, lines 56.76% — workflow line coverage up ~23 points over baseline (33.73% → 56.76%); no still-live workflow code lost coverage.
- Fully warm `cargo make test` (no recompilation): ~2.9s end to end; the new suites add ~1.5s of runtime.

## Phase 2 — WASM boundary

- The `adapter` world (`export source; export target;`) is enabled in `wit/specify.wit` as an additive combined world; external adapters remain single-axis.
- One combined `fixture_adapter` guest replaces the `echo_source` / `echo_target` examples; the shim is generated WIT conversions delegating to the same native core the workflow suites use.
- `harness/replay` is rewritten as `harness/composed`: one direct composed smoke (`fixture_component_drives_full_loop`) binding the same component at `source:fixture` and `target:fixture` with colocated scripted answers — no `scenario`/`quality` dependency and no replay-fixture corpus.
- Rung renamed: `cargo make test-wasm` (was `test-replay`); `.github/workflows/composed.yaml` runs `-p composed` and no longer builds the shipped binary. Measured: the smoke passes in ~66s (Wasmtime JIT dominates), guest build + test ~184s warm-deps — still scheduled/manual, not per push.
- The per-push `wasm` gate now also compile-checks the fixture-adapter shim (`cargo check -p fixtures --examples --target wasm32-wasip2`), so a WIT revision and its seam break in the same push.
- Deliberate coverage retirements: the shipped `specify` binary is now compile-only — the deleted binary smoke proved config loading + subprocess wiring, but `src/runtime.rs` is one `omnia::runtime!` invocation over upstream-owned mechanics and the composed smoke drives the identical hosting shape (same host set, `Mode::Command`, same manifest grammar) in-process; and `harness/quality`'s tests run on no cadence between this phase and their Phase 4 deletion.
- `cargo make test` remains green (263 tests); `cargo clippy -p fixtures -p composed --all-targets` clean.

## Phase 3 — live quality

- New non-default member `harness/live` holds the one explicit live-model workflow test (`adversarial_loop_is_validator_clean`, `#[ignore]`): the same fixture workflow over the adversarial lead set — cross-source overlap, authority disagreement, evidence gap — against the configured cursor model, graded by the deterministic validators only (kernel coverage, schema gates, provenance completeness, `[divergence]`/`[unknown]` tags, drained lifecycle, non-empty build outputs). Structural assertions are name-agnostic since slice and domain names are model-chosen.
- The test shares `crates/workflow/tests/common/` via a `#[path]` module (the established `fs_git.rs` pattern), so fixture behaviour has exactly one provider bridge; the cursor binding is a local ~150-line shim over `omnia_cursor::Client` mirroring the guest→wire mapping the wasm default body performs.
- Isolation: the live package is tests-only and outside `default-members`, keeping `omnia-cursor → omnia → wasmtime` out of the per-commit compile path (acceptance #8: default tests compile no Wasmtime).
- Rung exposed as `cargo make test-live` (`--run-ignored all --no-capture`); single trial, never CI. Per-leg repair counts are reported (not asserted) from the recording harness by judgment schema name (`proposal` / `synthesis`). The temporary project tree is retained on failure and printed at start.
- Cadence documented in `harness/live/README.md`: before a release tag and after judgment-prompt (`crates/workflow/prompts/`) or answer-schema changes.
- Verified: the package compiles, clippy-clean, and the ignored test is enumerated (`cargo nextest list -p live --run-ignored all`). A live run on this machine reached the cursor backend and failed only on authentication (`cursor-agent` not logged in, no `CURSOR_API_KEY`), confirming the dispatch path end to end; a credentialed run is pending operator invocation.
- Phase review: APPROVED. Applied post-review: `test-live` uses `--no-tests=fail` so an empty run cannot read green (the operator invocation is the rung's only cadence); the baseline assertions parse requirement blocks with `artifacts::spec::provenance::parse_spec_md` instead of substring counting (non-`unknown` requirements must carry non-empty `Sources:`); the cursor shim documents its deliberate, drift-prone duplication of `specify-adapters/harness/native/src/model.rs` in-file. Accepted as-is: synthesis repair counts aggregate across slices (per-slice partitioning derivable from `Execute` ordering if ever needed).

## Phase 4 — machinery removal

- Deleted: `crates/scenario`, `harness/quality`, the `quality/` tree, `scripts/dev.rs`, the root `omnia.toml` dev manifest, `schemas/authoring/scenario.schema.json` + `SCENARIO_JSON_SCHEMA`, `tests/framework/scenarios.rs`, and the `dev` / `quality` Make tasks. No surviving plugin fixture consumed the scenario schema or framework scenario checks.
- Resolver: the hard-coded sibling `specify-adapters` probe is gone — bare-name resolution is project-contained (project component cache, then the project's own `target/wasm32-wasip2/release/<name>.wasm`). New resolver tests cover the project-cache hit and assert the old sibling location no longer resolves (`bare_identity_from_project_cache`, `sibling_checkout_never_probed`); store/pinned resolution keeps its existing coverage.
- Prose swept in the same change: `docs/contributing/{checks,index}.md`, `docs/SUMMARY.md`, the legacy-migration tutorial, orientation prerequisites, `harness/README.md`, the plan-fixtures README, and the mechanical AGENTS.md hits (crate graph, repo map, test-surface paragraph, sibling-resolution gotcha). `docs/contributing/{quality-profiles,skills-test-coverage}.md` deleted. Deep rewrites of `testing.md` / `dev-loop.md` / `quality-gates.md` / `project.mdc` remain Phase 5.
- Gate: `cargo make check` green (fmt, clippy `-D warnings`, wasm gate, 234 native tests, doctests, doc); `cargo make test-wasm` green (composed smoke 103s); `cargo llvm-cov nextest -p workflow`: regions 58.99%, functions 62.55%, lines 57.67% — no loss against Phase 1 (58.29 / 62.00 / 56.76).
- Phase review: CHANGES REQUIRED → resolved. Must-fix: `schemas/README.md` still cataloged the deleted `authoring/scenario.schema.json` with a dangling link that `links.rs` never scans (row removed). Should-fixes: `docs/contributing/cli-architecture.md` claimed the deleted repo-root `omnia.toml` names the dev build (claim removed); the positive local-`.wasm` init leg — mirror into the project component cache plus the downstream bare-name resolve — had no test (added `scaffold::local_component_mirrored`, now the only route an externally built adapter has into a project). Nits: the `adapter-not-found` / GitHub-URI remediations said `cargo make release` (an adapters-repo task) — reworded to `cargo build --release --target wasm32-wasip2`; `docs/standards/workflow.md` §Resolver dropped the sibling probe step. The stale `scripts/dev.rs` GitHub URL in `dev-loop.md` lands with that file's Phase 5 rewrite.

## Phase 5 — documentation rewrite

- `docs/standards/testing.md` rewritten around the three rungs (native / composed smoke / explicit live trial) plus the fixture-adapter boundary; integration-first policy, the three layers, coverage brake, naming, goldens, and gotchas retained. `docs/contributing/dev-loop.md` rewritten as the self-contained loop (`test` / `test-wasm` / `test-live`, what CI runs). `docs/contributing/quality-gates.md` rewritten as the three-gate model with placement decision and boundaries; scenario/profile/rubric vocabulary and gates 2–4 removed.
- Swept in the same phase: `.cursor/rules/project.mdc` (validation paragraph + layout), `docs/standards/architecture.md` (crate graph row `scenario` → `harness/fixtures`, dev-only-exception paragraph, both resolver-probe descriptions), `docs/explanation/adapter-anatomy.md` (documents the additive combined `adapter` world with no new obligations for single-axis adapters), `docs/book.toml` (dead linkcheck exclusions), `docs/release.md` (before-tagging rungs), and the last AGENTS.md line assigning composed-deployment posture ambiguously.
- Cross-repo sweep (`specify-adapters`): deleted the `dev` task that invoked the removed `specify/scripts/dev.rs`; TESTING.md/README.md/harness manifests now describe pin co-development as hand-supplied `--config` path patches; the live-run examples use the direct `cargo test -p harness --test live` invocation; `model.rs`'s credential hint no longer points at `dev -- doctor --live`; TESTING.md rung 6 routes dev components through `specify init <path>.wasm` instead of the removed sibling probe. The `harness/native` scenario-crate usage stays as-is — it runs against its declared engine pin and migrates when that pin advances (engine test coupling is not restored).
- Gate: `cargo make test` green, framework link/prose checks green, repo-wide stale-reference search clean (`test-replay`, `cargo make dev|quality`, `crates/scenario`, `harness/{quality,replay}`, `scripts/dev`, profile vocabulary — only `rfcs/` retains them, by design).
- Phase review: CHANGES REQUIRED → resolved. Must-fixes: the rewritten docs claimed `harness/fixtures` was a default member while `Cargo.toml` excluded it, leaving `fixtures::core` on no rung — resolved by adding it to `default-members` (the native core is dependency-free and the guest shim is `cfg(wasm32)`-gated, so no Wasmtime enters the default compile path; suite now 238 tests) and updating the four "crates/* plus tests/framework" call-outs; `README.md` still documented sibling-checkout resolution twice (now routes local adapter iteration through `specify init <path>.wasm`); one "sibling/in-repo" survivor in `adapter-anatomy.md`; the glossary's eight scenario/profile/rubric entries (Gate, Hard assertion, Model backend, Profile, Run report, Runtime, Scenario, Semantic rubric) rewritten around the three rungs or deleted. Should-fixes: dropped the dangling "eval scenario #7" pointer in `amend-plan-at-gate-1.md`; `tests/README.md` now names the engine-side testkit consumers instead of "the native harness and the sibling adapter suites". Nits: fixed the `handler-shape.md` anchor and re-homed the three-layer table's wire-contract row at `crates/transport/tests/` (the root package carries no test binaries).

## Final review and acceptance

- Aggregate review over the complete branch: APPROVED, no must-fixes. Resolved should-fixes: the fixture's `fail-merge` typed-failure profile was implemented but unbound — added `adapter_seam::merge_seam_failure_parks_slice_built` (merge preflight *dispatch* error → `seam-dispatch-failed`, slice stays `built`, no baseline write — distinct from the marker-file failed-report gates in `full_loop`); the two comments claiming the harness crates escape the per-commit compile path corrected (workspace-wide clippy compiles them; only the *test* path is default-members-scoped, which is what acceptance #8 requires). Nit resolved: the inner postflight failed-report code `target-merge-postflight-gate` renamed to the documented `target-merge-postflight-failed`. Accepted observations: the RFC's merge prose ("the engine merge path remains deterministic") is archival — the phased merge gates and Decision Records surfaces that co-evolved on this branch are documented in `docs/standards/workflow.md`, not the RFC.
- Housekeeping from the CI run: the orphaned `assert_cmd` workspace dependency (its consumers were deleted with the old harness) removed from `Cargo.toml` and the lockfile.
- Final gates: `cargo make ci` green (66s warm; vet/deny clean), `cargo make test` green (239 tests, ~2.4s runtime / fully-warm end-to-end ~3s vs the 271s warm Phase 0 baseline), `cargo make test-wasm` green (Phase 4 record, 103s), workflow coverage lines 57.67% vs 33.73% baseline.
- `cargo make test-live` **not run to completion**: the environment has no command-mode cursor credentials (`cursor-agent` exits with "Authentication required"; dispatch verified end-to-end). A credentialed run — recording the per-leg repair counts as the drift baseline — remains a pre-tag operator action.
