# Specify Refine

`/spec:refine` materialises one plan entry's slice directory, runs source `extract` serially, then drives the synthesis leg of the guest-routed `specify slice refine` to turn the resulting `Evidence[]` plus the target `shape` brief into the canonical artifacts and the typed `model.yaml`, validates, and transitions the slice to `refined`. The skill body owns the CLI choreography; the synthesis playbook at [`../../references/synthesis/`](../../references/synthesis/) owns what to write into the agent's synthesis **response** (claims, agreement verdicts, prose). The kernel owns every deterministic projection around that judgment — `REQ`/`TASK` ids, authority resolution, status, winner markers, rendered `Sources:` lists, and the inline provenance.

## Critical Path

1. **Resolve target and sources** — driver mutual exclusion is guest-owned: the guest-routed verbs hold the `.specify/guest.lock` marker for the run's lifetime (see [`../../references/plan-lock.md`](../../references/plan-lock.md)); a concurrent driver fails loudly host-side. Pick `$SLICE_NAME` from the operator argument; if absent, fall back to `specify plan next --format json` and halt with `refine-no-active-slice` when nothing is in-progress. Take the resolved `target` from the `specify plan next` response (resolved on demand from the slice's bound `project`) and read `sources[]` from `plan.yaml.slices[<slice>]`. Each binding supplies `(source, lead)`; bare-string shorthand `<key>` normalises to `{ key: <key>, lead: $SLICE_NAME }`. Cross-resolve every `key` against `plan.yaml.sources.<key>` and every `lead` against the `## Lead inventory` blocks in `discovery.md`; halt with `refine-binding-unresolved` on lookup failure.
2. **Workspace routing.** When `.specify/project.yaml` carries `workspace: true`, route per [`../execute/references/workspace-routing.md`](../execute/references/workspace-routing.md): `specify workspace sync $PROJECT`, `chdir` into `workspace/$PROJECT/`, and export `SPECIFY_PLAN_DIR=<workspace-root>` so the slot-side plan readers below (`source extract`, the `slice refine` synthesis leg, `slice validate`) resolve the workspace's `plan.yaml`. Restore CWD and unset the export before exit. Single-repo mode is a no-op.
3. **Create the slice directory** — `specify slice create "$SLICE_NAME" --target <target> --format json`. CLI stamps `metadata.yaml` at `refining`; this is the first step that materialises any path under `.specify/slices/$SLICE_NAME/`. On non-zero exit, surface the structured error and stop.
4. **Extract serially per binding** — walk `sources[]` in declaration order (no parallelism). For each `{ key, lead }`, run the guest-routed `specify source extract <source> <lead> --slice "$SLICE_NAME" --format json` orchestration: it resolves the bound source adapter, builds the sandbox roots, scaffolds the `evidence/` target, emits `source.execution.agent`, drives the adapter guest's `extract` brief against that prepared sandbox, then in its finalize tail validates the Evidence against `schemas/evidence.schema.json`, persists it to `.specify/slices/$SLICE_NAME/evidence/<source>.yaml`, and writes the journal event — CLI-owned, so the skill never persists Evidence or appends the journal line by hand. On `source-extract-path-denied` / `source-extract-failed`, stop the loop and print the extract-failure closing hint; the slice stays `refining` and the operator amends the plan (`--remove-source` / `--add-source`) before re-running.
5. **Synthesise (agent step)** — run the synthesis leg of the guest-routed `specify slice refine "$SLICE_NAME" --format json`. Its inputs side resolves the bound target's `shape` brief and assembles the **inputs** envelope (each bound source's inline `lead` + `claims` read from `evidence/<source>.yaml`, the resolved shape brief body, and — when the bound project carries a merged baseline — a `baseline[]` of the project's owned domains with their requirement titles plus optional `baseline-detail[]` with existing `req-ids` / `max-req-num` per domain; empty stays off the wire for greenfield), emits `slice.synthesize.agent`, and writes nothing. Read `baseline[]` to synthesise against existing requirements — extend or refine them rather than re-deriving overlapping behaviour from scratch. Author the **response** JSON against that envelope per [`../../references/synthesis/substeps.md`](../../references/synthesis/substeps.md) (which cites [`requirement-block.md`](../../references/synthesis/requirement-block.md), [`authority.md`](../../references/synthesis/authority.md), [`claim-reconciliation.md`](../../references/synthesis/claim-reconciliation.md), and [`spec-format.md`](../../references/spec-format.md)): for each requirement the contributing `(source, id, kind)` claims, an `agreement` verdict, and prose (`title`, `statement`, `scenarios`, `notes`, `domain`); set `baseline-id` when refining an existing baseline requirement in a modified domain, omit it for net-new behaviour. Plus the prose-only `proposal.md` / `design.md` / `tasks.md` bodies and per-`domain` spec bodies written **without** `ID:` / `Sources:` / `Status:` lines. Do **not** author `REQ`/`TASK` ids, `status`, `winner` markers, or `Sources:` lists — the kernel owns those (it normalises, never rejects, anything you supply). The persist tail then emits `slice.synthesize.started`, schema-gates the response, resolves authority from the on-disk Evidence and any per-slice `authority-override`, projects the kernel-owned fields (including baseline-aware ids and `## ADDED` / `## MODIFIED` delta sections for modified domains), renders provenance lines into each `specs/<domain>/spec.md`, auto-scans `metadata.touched_specs`, drift-validates, and atomically persists `proposal.md` / `specs/<domain>/spec.md` / `design.md` / `tasks.md` / `model.yaml`, emitting `slice.synthesize.completed`. On `slice.synthesize.failed` the prior artifacts stay intact and the slice stays `refining` — fix the response and re-run the synthesis. Tags never park the slice — proceed to step 6 regardless of tag count.
6. **Validate** — `specify slice validate "$SLICE_NAME" --format json` loads `model.yaml` and runs the typed-model drift validators (`slice-model-schema`, `slice-spec-provenance-stale`, `slice-model-target-drift`, `slice-model-source-orphan`, `slice-model-cross-ref-orphan`, `slice-model-claim-kind-mismatch`, `slice-model-id-grammar`), the provenance parser over the kernel-rendered `spec.md` lines, and the Evidence schema validator. The CLI renders a `DiagnosticReport` on stdout — `kind: violation` findings are blocking defects; `kind: review` findings are the semantic checks raised for your judgment and never block (read your worklist as `findings.filter(kind == "review")`). On success the CLI appends synthesis-tag journal events per [`../../references/synthesis/tags.md`](../../references/synthesis/tags.md) §Journal-event hand-off (one line per tagged requirement; CLI-owned). On non-zero exit, surface the stdout report plus the payload-free error envelope (its `error` is the gate discriminant) verbatim, do **not** transition, and print the validation-failure closing hint; common causes are an operator hand-edit that staled a kernel-rendered provenance line (`slice-spec-provenance-stale`), a claim referencing an absent `(source, id)` (`slice-model-source-orphan`), or Evidence missing `id` on a `requirement` / `criterion` claim.
7. **Transition to refined** — `specify slice transition "$SLICE_NAME" refined --format json`. CLI emits `slice.transition.refined`. Print the closing hint.

> **Provenance is not a hand-written file.** There is one structured slice artifact — `model.yaml` — carrying provenance **inline** on each requirement; the synthesis kernel inside `specify slice refine` is its sole writer, and `specify slice provenance` projects the audit view on demand. The refine skill does not author a `provenance.yaml`. See [`../../references/synthesis/provenance.md`](../../references/synthesis/provenance.md).

> **Decision Records (optional).** When the slice makes a design *decision* worth keeping — an architectural choice plus the alternatives it rejected — author one Decision Record per choice as a hand-written file at `.specify/slices/$SLICE_NAME/decisions/<slug>.md` (YAML front-matter + a `## Context` / `## Decision` / `## Consequences` Nygard body; the agent authors `slug` and `status: accepted | rejected` only — plus an optional `topics:` list of kebab-case domains the decision governs, which becomes the plan-time `lead-decision-topic-overlap` join key — and `specify slice merge` assigns the durable `DEC-NNNN`). These are agent-authored prose, not kernel-projected from `model.yaml`; step 5 `specify slice validate` gates their shape (`decision-record-*` findings). See [`../../references/artifact-conventions.md`](../../references/artifact-conventions.md) (Decision Records section). Slices that take no notable decision author none — the directory is opt-in.

## Closing hint

On success:

```text
Slice <slice-name> refined. spec tags: <U> unknown, <C> conflict, <D> divergence. Review .specify/slices/<slice-name>/specs/, then run /spec:build <slice-name> or resume /spec:execute.
```

On extract failure (any binding):

```text
Refine halted: source <source> extract failed (<error-code>). Slice <slice-name> stays refining. Amend the plan (specify plan amend <slice-name> --remove-source <source>, or --add-source <source>=<lead>) and re-run /spec:refine <slice-name>.
```

On validation failure:

```text
Refine halted: synthesis output failed validation (<error-code>). Slice <slice-name> stays refining. Fix the synthesis response and re-run specify slice refine <slice-name> (the kernel owns provenance — never hand-edit ID:/Sources:/Status: lines), then specify slice transition <slice-name> refined.
```

These three shapes are the contract `/spec:execute` matches when invoking refine as a loop step or as a breakout.

## Guardrails

- **Lifecycle single-writer:** [shared guardrails](../../references/guardrails.md#single-writer-for-lifecycle-state).
- **Never materialise `.specify/slices/$SLICE_NAME/` outside step 3.** `specify slice create` is the sole writer; before step 3 the on-disk shape is plan-only.
- **Never run `extract` in parallel.** Bindings are processed in `slices[].sources[]` declaration order; deterministic goldens depend on it.
- **Never park the slice on tags.** `[unknown]` / `[conflict]` / `[divergence]` are review signals; the slice still transitions to `refined`. A `slice.synthesize.failed` (or a post-persist `specify slice validate` failure) is the only condition that keeps the slice in `refining` after extract succeeds.
- **Never author kernel-owned fields.** The synthesis response carries claims, `agreement` verdicts, and prose only. `REQ`/`TASK` ids, `status`, `winner` markers, and rendered `Sources:` lists are the kernel's — supplying them is harmless (it normalises) but pointless, and hand-editing the kernel-rendered `ID:` / `Sources:` / `Status:` lines in `spec.md` staleness-fails `specify slice validate`.
