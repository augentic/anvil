# Augentic Governance

This document defines the project governance for the Augentic Specify plugins repository.

## Principles

The Augentic community adheres to the following principles:

- Open: Augentic is open source. See repository guidelines and processes below.
- Welcoming and respectful: See [Code of Conduct](#code-of-conduct), below.
- Transparent and accessible: Work and collaboration are done in public.
- Merit: Ideas and contributions are accepted according to their technical merit and alignment with project objectives, scope, and design principles.

## Maintainer Role

Maintainers are responsible for the project as a whole: guiding direction, reviewing PRs, performing releases, and ensuring quality of skills, schemas, and documentation.

## Changes in Maintainership

New maintainers are proposed by an existing maintainer and accepted by consensus among current maintainers. Maintainers can step down by notifying the team.

## Decision Making

Decisions are resolved by consensus among maintainers. If consensus cannot be reached, a simple majority vote among maintainers determines the outcome.

## GitHub Project Administration

Maintainers will be added to the Augentic GitHub organization.

## Approving and Merging PRs

All PRs must receive approval from at least one maintainer prior to merging.

## Changes in Governance

All changes in governance require consensus among maintainers or a 2/3 majority vote.

## Code of Conduct

Augentic follows the [CNCF Code of Conduct](https://github.com/cncf/foundation/blob/main/code-of-conduct.md).
